# Industrial Brand Icon Design — Recent Failure Cases 15–24

这些案例来自近期真实使用中的反复失败。它们是新版质量门禁的 RED 基线，不是随意扩展的假设需求。

## Case 15 — Smart Detect / Quick Scan / Complete Scan

**输入：** 生成 `Smart Detect / Quick Scan / Complete Scan` 三个图标。副文案分别为自动识别车辆信息、检查常用系统、扫描全部可用 ECU。

**通过标准：**

- Smart Detect 表达车辆身份信息被自动识别；
- Quick Scan 表达有限或常用系统范围被快速检查；
- Complete Scan 表达全部 ECU 或完整系统覆盖；
- 三枚共享诊断语境，但核心结构具有明确差异；
- 不依赖标题时仍能理解自动识别、部分范围、完整范围的大致方向；
- 生成前通过语义、系列与简洁门槛。

**失败条件：**

- 三枚都是相同汽车、设备或放大镜，只更换小符号；
- Quick 与 Complete 只靠难以辨认的小点数量区分；
- Smart Detect 退化为普通扫描；
- 用灯泡、星星、齿轮等装饰替代自动识别语义。

## Case 16 — Fast / Stable / Responsive

**输入：** 生成 `Fast / Stable / Responsive` 三个硬件性能图标。

**通过标准：**

- Fast 表达完成过程耗时更短；
- Stable 表达输出连续、无中断或明显波动；
- Responsive 表达输入后立即产生对应反馈；
- 允许共享芯片或信号语境，但主结构必须可区分；
- 三枚线面、重量、视觉盒与重心统一。

**失败条件：**

- 三枚都以闪电为核心；
- Stable 只用一条无意义横线；
- Responsive 只有手指或按钮，没有输入与反馈关系；
- 三枚脱离汽车诊断或硬件性能语境，变成普通互联网图标。

## Case 17 — 五种 DPF 异常状态

**输入：** 生成 `DPF / Check Engine Lights / Reduced Engine Power / DPF-Related Fault Codes / High Soot Load / Repeated Active Regen Failures` 对应的五枚图标。

**通过标准：**

- 五枚共享 DPF 或重卡诊断语境；
- 告警、降功率、故障码、高积碳、再生失败清楚区分；
- 第一枚具有明确警告灯认知；
- 整组线粗、构造语言、黑度、视觉盒与重心统一；
- 主轮廓差异足以避免同模具感。

**失败条件：**

- 五枚使用相同 DPF 外壳，只更换角标；
- 为了差异而使用五种不相关视觉语言；
- 任一成员需要完全依赖标题才能猜测核心状态。

## Case 18 — 硬件与防护八图

**输入：** 生成 `Spark-proof Clips / Reverse Polarity Protection / Fast / Stable / Responsive / Water / Dust / Oil Resistant`。

**通过标准：**

- 鳄鱼夹完整可辨；防火花与反接保护具有不同核心关系；
- 性能三图符合 Case 16；
- Water、Dust、Oil 具有不同威胁身份；
- 八枚近方占位、光学重心、线面和细节等级一致；
- 不使用相同底线、盾牌或外框制造统一。

**失败条件：**

- 防火花夹主体残缺；
- Water、Dust、Oil 实际是相同水滴换细节；
- 同组混用纯线、重实心与剪影；
- 某枚明显过长、过空、过黑或复杂度异常。

## Case 19 — 评分真实性压力测试

**输入：** “按默认规范直接生成，不用分析，赶时间。”

**通过标准：**

- 内部仍完成必要语义比较、系列规划和质量门禁；
- 不向用户展示冗长评分过程；
- 不因时间压力跳过硬性否决；
- 未达门槛时静默重构，不能声称已经通过；
- 达到停止条件后询问一个关键问题，不交付伪合格结果。

**失败条件：** 直接生成第一个想到的方案，或只写一句“已内部评分”而无可观察决策证据。

## Case 20 — 指定成员修改与全局线粗

**输入：** “只优化第一个图标，其余四个外观不变，整体图标粗细均改成 5px。”

**通过标准：**

- 第一枚可按反馈重新设计；
- 其余四枚锁定主体、动作、构图、比例和关键细节；
- 五枚只同步线粗；
- 加粗或变细后轮廓、孔洞和比例不变形；
- 最终仍复核整组，复核不等于重画。

**失败条件：** 未指定成员被重新设计，或线粗调整同时改变内部结构。

## Case 21 — 视觉锚点与未点名复核

**输入：** “第二、第三个跟第一个统一，第一枚保持不变。”

**通过标准：**

- 第一枚成为硬锁定视觉锚点；
- 第二、第三枚向其构造语言、线面节奏和重量靠拢；
- 第一枚仍被复核，但不得修改；
- 第二、第三枚保留自己的核心语义和主轮廓。

**失败条件：** 重画第一枚，或给三枚套相同外框制造统一。

## Case 22 — 十三枚大系列压力测试

**输入：** 根据截图文案生成 13 枚汽车或重卡诊断功能图标。

**通过标准：**

- 先按系统、动作、状态或利益类型分组；
- 检查主体重复、语义碰撞和天然长短差异；
- 先建立共享参数再设计成员；
- 从第一枚到第十三枚保持线粗、黑度、复杂度和重心稳定；
- 数量准确，所有成员进入最终整组检查。

**失败条件：** 前后成员质量漂移、遗漏数量、依赖同一模板，或后半组明显简化敷衍。

## Case 23 — The Noun Project 参考边界

**输入：** “可以参考 The Noun Project 的图标样式。”

**通过标准：**

- 学习公共认知、简洁轮廓、负空间和小尺寸可读性；
- 不复制具体图标或受保护的独特表达；
- 不自动把品牌默认改成纯线、大圆角或通用素材风；
- 将本次参考先视为 A 级，除非用户另行确认长期级别。

**失败条件：** 直接照搬具体图形，或用外部网站风格覆盖现有语义与品牌规则。

## Case 24 — 纯线风格单次覆盖

**输入：** “参考车型图，生成十个统一的纯线车辆图标。”

**通过标准：**

- 本次纯线要求覆盖默认线面结合；
- 车型身份、真实比例、线粗、占位和重心保持；
- RV、卡车、船等长形主体通过重构占位而非拉伸压扁；
- 单次覆盖不改写长期默认。

**失败条件：** 强行加入实心面，或为了近方占位破坏车辆身份和真实比例。
