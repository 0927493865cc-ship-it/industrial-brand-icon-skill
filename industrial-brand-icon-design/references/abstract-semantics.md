# 抽象功能语义处理

当文案描述智能、速度、稳定、响应、便利、兼容、节省、防护或范围，而不是一个明确实体时，读取本文件。

## 1. 先改写为可观察行为

不得看到抽象词就直接套闪电、盾牌、灯泡、星星、对勾或箭头。先写出用户能观察到的行为或结果。

| 抽象词 | 可观察行为 |
|---|---|
| Smart | 系统自动完成了什么识别或判断 |
| Quick / Fast | 哪个明确过程耗时更短 |
| Complete | 哪些对象被完整覆盖 |
| Stable | 信号或运行状态连续、不中断、不明显波动 |
| Responsive | 输入后立即产生对应反馈 |
| Carry Less | 携带对象数量、体积或负担减少 |
| Easy to Use | 操作步骤减少或路径更直接 |
| Compatible | 多种明确对象能够连接或正常使用 |
| Safety | 哪一种具体危险被阻止、隔离或纠正 |

## 2. 表达阶梯

按顺序选择：

1. 直接对象；
2. 对象发生的动作；
3. 可观察状态变化；
4. 用户最终结果；
5. 公共认知隐喻。

只有前一层无法清楚表达时才下移。每枚图标最多允许一次认知跳转；需要连续解释两次以上的方案直接打回。

## 3. 扫描层级三图

`Smart Detect / Quick Scan / Complete Scan` 的视觉语义分别是：

- 车辆身份信息被自动识别；
- 一组常用或有限范围的系统被快速检查；
- 全部可用 ECU 或系统被完整覆盖。

三枚应共享诊断语境，但不能都使用相同汽车、设备或放大镜。Quick 与 Complete 的“部分/全部”必须进入主结构，不能只靠微小点数变化；Smart Detect 不能退化成普通扫描。

## 4. 性能三图

`Fast / Stable / Responsive` 分别强调：

- 时间效率；
- 连续性；
- 输入与反馈的因果关系。

可以共享芯片、信号或系统语境，但不得三枚都用闪电。Stable 不能只是一条无意义横线；Responsive 必须同时存在可识别的输入和反馈关系。

## 5. 防护三图

`Water / Dust / Oil Resistant` 可以共享“外部侵入被阻挡”的关系，但威胁对象必须不同：

- Water：水滴或水流；
- Dust：颗粒或粉尘；
- Oil：具有油液身份的黏稠滴状或污染状态。

统一依靠线粗、构造、重量、占位和防护关系，不依靠三个相同水滴、底线、盾牌或外框。

## 6. 利益类文案

`Save Money / Save Time / Carry Less / Ease of Use` 优先表达真实变化，而不是情绪：

- 节省什么、减少什么、合并什么；
- 操作前后对象数量或步骤如何变化；
- 是否需要汽车诊断语境，或用户明确要求通用表达。

例如 Carry Less 优先理解为携带对象数量或负担减少；若用户要求通用图标，再压缩为通用负载变化，而不是直接使用羽毛。

## 7. 内部检查

每枚抽象图标生成前必须回答：

1. 这个词对应什么实际行为？
2. 用户能看到什么变化？
3. 哪个对象承载该变化？
4. 不看标题能否理解大致方向？
5. 与同组最接近功能的主结构差异是什么？
6. 是否用了过度通用的符号？
7. 是否需要两次以上解释？
8. 能否再删一个元素而不损失身份或含义？

任一项没有清楚答案，不进入生成。
