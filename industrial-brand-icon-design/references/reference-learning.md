# 图标 Skill 参考学习与迭代机制

本文件负责 Skill 如何从新参考图、失败案例和真实项目反馈中持续学习，同时避免被单次偏好带偏。

## 1. 四级证据体系

任何新经验先判断级别：

- **A级｜单次参考**：只服务当前任务，不进入长期核心。
- **B级｜项目规则**：只对某个产品、项目或产品线长期有效。
- **C级｜品牌稳定规则**：多个项目反复验证，形成长期稳定品牌偏好。
- **D级｜底层方法论**：改变整个设计判断、生成、反馈或验收流程的规则，整个 Skill 都要遵守。

判断口诀：

- 只是这次喜欢 → A级
- 这个项目以后都这么做 → B级
- 多个项目都反复喜欢 → C级
- 不这么做整个设计逻辑就容易出错 → D级

级别不是越高越好，放对位置最重要。

## 2. 新反馈默认不直接进入核心

任何新参考图或反馈先观察，除非它明显属于底层方法论。

升级依据包括：

- 同一项目内多次验证；
- 跨项目重复验证；
- 能稳定解决历史失败；
- 通过固定 Eval；
- 明显提升识别、系列一致性或小尺寸表现。

## 3. 好参考图要“拆着学”

用户说“把这张图喂进 Skill”时，不得整套照搬。

至少分析：

1. 认知：为什么第一眼能懂；
2. 主体：核心对象怎么选择；
3. 构图：主体占比、长宽比例、重心；
4. 线条：粗细、主次线关系；
5. 线面：纯线、线面结合、实心比例与作用；
6. 转角：硬朗、轻圆角、大圆角；
7. 内部密度与负空间；
8. 动作符号如何出现；
9. 小尺寸为什么还能清楚；
10. 系列统一靠什么实现。

然后输出：

- 值得吸收；
- 不建议吸收；
- 与现有规则一致之处；
- 冲突之处；
- 建议 A/B/C/D 哪一级；
- 是否需要新增 Eval。

原则：**不是喂“图”，而是喂“规律”。**

## 4. 认知参考与视觉风格必须分开

例如仪表盘 DPF 灯可能非常适合帮助理解 DPF，但它解决的是“画什么”，不是“所有图标以后都长成仪表盘灯”。

认知参考进入 `semantic-guide.md`；稳定视觉特征进入 `style-guide.md`；项目特例保持 B 级或 A 级。

## 5. 失败案例必须反向学习

失败图通常比好图更容易形成禁止规则和修正路径。

收到负面反馈时，先判断失败类型：

- 语义失败：意思表达错；
- 结构失败：太空、太满、太长、主体太小、缩小糊；
- 风格失败：太细、太软、太圆、纯线、剪影化；
- 系列失败：重心、黑度、线面、尺寸、复杂度不统一；
- 表达失败：隐喻正确但理解路径太绕。

每个失败案例记录：

- 失败现象；
- 失败层级；
- 原因；
- 修正方式；
- 当前级别；
- 是否需要新增测试。

## 6. 局部反馈，整体重审

用户只指出某些图标有问题时，未被点名图标不能自动视为通过。

流程：

1. 用户明确问题优先修正；
2. 重新思考整套体系；
3. 未点名成员重新检查语义、结构、风格和系列适配；
4. 只有复核通过后，才可作为视觉锚点；
5. 局部修改后必须重新验收整组。

## 7. 规则冲突处理

当前明确任务要求优先于长期视觉默认，但不得跳过 D 级底层方法论。

长期规则冲突时：

1. 先找兼容解；
2. 比较证据数量与质量；
3. 比较是否经过 Eval；
4. 比较哪条更具体、更符合当前任务；
5. 必要时升级、降级、修改或删除旧规则。

例如“偏正方形”与“保留真实对象比例”并不必然冲突，应通过缩短非关键延伸和重新构图解决，而不是拉伸对象或二选一。

## 8. 连续例外说明规则写得太死

如果一条规则不断出现例外，应修改规则本身，而不是无限堆例外。

例如：

旧规则：“禁止悬浮元素。”

多次遇到升级、下载、删除等必要动作后，应改为：

“辅助语义优先整合；当通用动作符号是理解所必需时，允许最多 1 个受控悬浮动作符号。”

## 9. 规则生命周期

每次迭代只允许以下动作：

- 新增；
- 修改；
- 删除；
- 升级；
- 降级；
- 合并。

Skill 不能只会增加长度。被更准确规则覆盖、与长期反馈持续冲突、重复、模糊或无法执行的旧规则应删除或合并。

## 10. 素材库组织

长期素材建议分三类：

### 好案例

记录什么做对了，为什么有效。

### 失败案例

记录不能再犯的错误、失败原因与修正路径。

### 认知参考

记录某个目标用户最熟悉的行业、仪表盘、车内或通用符号认知。

每个素材都应有简短“学习卡”：

- 类型；
- 值得学；
- 不吸收；
- 当前级别；
- 影响哪些规则；
- 是否需要 Eval。

原则：**规则是结论，素材库是证据。**

## 11. 更新前后的测试保护

任何长期规则更新都必须：

1. 先更新或新增 Eval；
2. 跑历史 Eval；
3. 跑新增 Eval；
4. 检查是否修一个问题却破坏旧能力；
5. 通过后才保留长期规则。

没有测试支持的规则，不应轻易升级到 C 级或 D 级。

## 12. 生成提示的规则筛选

Skill 内部可以有很多规则，但每次生成只调用当前任务相关的规则。

全局规则通常包括：

- 先理解再生成；
- 系列先规划；
- 1 主体 + 0–1 必要辅助语义；
- 线面结合；
- 偏正方形；
- 水平重心；
- 内部不过空不过密；
- 小尺寸可读。

对象特殊规则只在相关任务调用，例如 ECU 字母、DPF 认知、Battery 外轮廓、Upgrade 箭头。

原则：**Skill 内部允许复杂，最终执行必须经过筛选和压缩。**

## 13. 定期清理

定期复盘：

- 删除重复规则；
- 合并相似规则；
- 降级一次性偏好；
- 删除已被新规则覆盖的旧描述；
- 检查同级冲突；
- 检查历史失败是否已被测试覆盖。

目标是让 Skill 越来越精确，而不是越来越臃肿。
